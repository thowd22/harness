## Memory
You have a long-term memory tool. Search it when past preferences or gotchas may apply. Save a memory (one bullet, one lesson) when:
- the user corrects you: save the rule to follow next time, not the mistake;
- the user states a preference about how to work;
- a decision is made: save it with its reason;
- you discover a gotcha about this repo, the environment or a tool that cost time.
Do not save session summaries, task state (PR or issue numbers, statuses, what is in progress), facts anyone can rediscover by reading the repo, or secrets. Put several lessons for one note in one write (`bullets`). If asked to index or learn the codebase into memory, save one compact project/overview note plus the non-obvious gotchas, not a file or module map, and tell the user the rest is re-read from the repo each session. New memories apply to future sessions.
